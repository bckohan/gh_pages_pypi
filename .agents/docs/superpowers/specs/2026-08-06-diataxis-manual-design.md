# Diátaxis Documentation Manual — Design

**Date:** 2026-08-06
**Status:** Approved

## Problem

The Sphinx docs are a stub: `index.rst`, an autodoc `reference/index.rst`,
and the changelog. The project now has seven substantial features and three
viable deployment targets, none of which are documented anywhere but the
README. Build a full manual on the [Diátaxis](https://diataxis.fr/)
framework.

## Decisions

- **Explanation lives on the index**, which includes the README body via
  **myst-parser** (`.. include::` with `:parser: myst_parser.sphinx_`) so the
  two can never drift.
- **CLI reference generated by `sphinxcontrib-typer`** — renders the real
  command tree from the typer app.
- **Tutorials are standalone end-to-end**, one per deployment target
  (GitHub Pages, Cloudflare, nginx). Diátaxis: a tutorial must guarantee
  success without side trips, so shared setup is repeated rather than
  cross-referenced.
- **How-to guides are FAQ-framed** ("How do I …?", "Why does …?").
- New docs-group dependencies: `myst-parser`, `sphinxcontrib-typer`.

## Structure

```
doc/source/
  index.rst                  explanation + README body (myst include)
  tutorials/
    index.rst
    github-pages.rst         zero → installable index on Pages
    cloudflare.rst           zero → index on Cloudflare Pages (+ Workers note)
    nginx.rst                zero → index behind nginx, incl. content negotiation
  how-to/
    index.rst                FAQ-framed task guides (see list below)
  reference/
    index.rst
    configuration.rst        every YAML key: type, default, constraints, example
    cli.rst                  sphinxcontrib-typer
    api.rst                  the existing autodoc source reference
  changelog.rst
```

## Explanation (index)

`index.rst` keeps its title/badges block, then includes the README body
between HTML-comment markers, then the toctree. The README gains
`<!-- docs-index-start -->` / `<!-- docs-index-end -->` markers around the
narrative (excluding the badge block, which stays GitHub-only).

Beneath the included body, index.rst adds a short **Why this design**
explanation section that belongs in docs rather than the README: why a
static index instead of a server, why release assets are a reasonable
package store, the trust model (`#sha256=` fragments, digest verification),
and when *not* to use this (private repos without mirroring, >100 releases).

## Reference: configuration

One table-of-contents-linked section per key, each stating type, default,
required/optional, constraints, and a YAML example:

| key | type | default |
| --- | --- | --- |
| `repositories` | list[str] `OWNER/NAME` | required, non-empty, no duplicates (case-insensitive) |
| `title` | str | `"Package index"` |
| `url` | str (https) | none — enables the absolute `--extra-index-url` example |
| `templates` | path (relative to the config file) | none |
| `formats` | list of `html` / `json` | `[html, json]` |
| `missing_digest` | `download` / `no-fragment` / `omit` | `download` |
| `mirror` | bool | `false` |
| `metadata` | bool | `true` |

Also documents cross-key rules (`missing_digest` rejected with
`mirror: true`), the `--mirror`/`--config` CLI conflict, and every
`ConfigError` message with its cause.

## How-to guides (FAQ-framed)

1. How do I serve packages from a **private** repository?
2. How do I aggregate **several repositories** into one index?
3. How do I **customize the look** of the index pages?
4. How do I make **rebuilds fast** for a large index?
5. How do I publish **PEP 658 metadata** for my wheels?
6. How do I serve the **JSON API at the canonical URLs**?
7. How do I stop pip from resolving my package **from pypi.org instead**?
8. What happens when a **release or file is deleted**?
9. Why is my index **empty** / why did the build fail?
10. How do I host the index **somewhere other than GitHub Pages**?

## Tutorials

Each: prerequisites → publish a release with wheels → build the index →
deploy → prove it by `pip install`-ing from the index → what to explore
next. Concrete, copy-pasteable, no branching decisions.

- **github-pages.rst** — Settings → Pages → Actions, the pages workflow,
  the release workflow, the live URL.
- **cloudflare.rst** — Cloudflare Pages project, build command, `_headers`
  for caching, note on Workers for content negotiation/private assets.
- **nginx.rst** — build locally or in CI, rsync/serve from a directory, an
  nginx `server` block with `Accept`-based JSON negotiation, `.metadata`
  MIME type, optional basic auth.

## README updates

- Add the `<!-- docs-index-start/end -->` markers.
- Convert repo-relative links (e.g. `[release.yml](.github/workflows/…)`)
  to absolute `https://github.com/bckohan/ghr-pypi/blob/main/…` URLs so they
  resolve both on GitHub and in the rendered docs.
- Add a "Documentation" line near the top pointing at the RTD site.
- Trim nothing substantive — the index mirrors it deliberately.

## Verification

- `just check-docs` (doc8) and `just build-docs-html` clean; sphinx
  `-W`-level warnings avoided (no broken refs, no orphan pages).
- `just check-all` exit 0 (includes linkcheck — all external links must
  resolve).
- Every documented config key and CLI option cross-checked against
  `config.py` / `cli.py`; every documented `ConfigError` string grepped to
  confirm it exists.

## Out of scope

- Translating the manual; versioned docs beyond RTD defaults; screenshots;
  a Workers/redirector implementation (phase 4 of `direction.md`).
